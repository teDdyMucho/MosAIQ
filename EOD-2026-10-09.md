# EOD — RavMizAI v4.1
**Oct 9, 2026**

Moved card capture into signup, added billing self-service and password reset,
and removed the last prototype card form.

---

## What was built

### 1. Card is taken at signup (client request)
Signup now goes straight to Stripe Checkout instead of dropping the new user on
the app home. The 7-day trial starts at checkout; the first $18 charge follows
automatically.

- Signup page says plainly: *"A card is required; you won't be charged until the
  trial ends"* and *"7 days free, then $18/month."*
- If checkout cannot open, the user still lands on the site with an explanation
  rather than a dead end
- Works the same from the verify page, for when email confirmation is turned on

**Proved the automatic charge** using a Stripe test clock — advanced time 8 days:
`trialing → active`, invoice `amount_paid = $18.00`. Not inferred.

### 2. Show password + confirm password
- Eye toggle on signup, login and the trial page
- Confirm field on signup and trial; blocks mismatches before Stripe
- Keeps the caret position, so toggling mid-typing does not interrupt

### 3. Billing self-service
`Membership & Billing` was decoration — hardcoded "Card ending in 4242", and the
Cancel button had no handler at all. A customer could not have cancelled.

Now real, via Stripe's hosted Billing Portal:
- Shows the actual card on file
- **Manage billing & cancel →** opens Stripe for card changes, invoices, cancel
- `supabase/functions/billing-portal/index.ts` — deployed
- `sql/005_card_summary.sql` — card brand + last4 only (never a full number)

### 4. Forgot password
- `forgot-password.html` — request a reset link
- `reset-password.html` — set a new password (toggle + confirm)
- Link added to the login page

The response is identical whether or not the address is registered, so the page
cannot be used to discover which emails have accounts.

### 5. Prototype card form removed
`trial/payment.html` collected card details itself and could only produce a
generic error, because no processor was ever called. It now hands off to Stripe,
which reports the real reason: *"Your card was declined"*, *"Incorrect CVC"*,
*"Your card has expired"*.

This answers Mike's note about the error being too generic.

## Bugs found and fixed

1. **The eye button broke signup, silently.** The submit button had no `type`,
   so the first button in the form became the default submit — and that was now
   the password toggle. Pressing "Create account" did nothing: no error, no
   redirect. Fixed by giving every submit button an explicit `type="submit"`.

2. **Card summary was always empty.** My own bug. The webhook only read
   `invoice_settings.default_payment_method`, but Stripe Checkout attaches the
   card to the *subscription* instead. It now checks three places. Backfilled
   the four existing accounts that had a card in Stripe.

## Note on cancellation

Cancelling during the trial keeps access until the trial ends (Stripe's
`cancel_at_period_end`), then charges nothing. This is standard and is what the
Stripe portal shows. It is deliberate — someone who has paid for a period should
keep it. Say so if the client wants access cut immediately instead.
