## Bug found and fixed

**Cancelling a subscription did not remove access.**

`apply_stripe_subscription()` declared `RETURNS TABLE (user_id ...)`, which made
`user_id` ambiguous against `trials.user_id`. The cancel path raised Postgres
error 42702 and aborted — but the webhook still returned HTTP 200, so the
failure was silent. Nothing would have alerted you.

Had this reached production, a customer could cancel and keep access forever.

Fixed by renaming the OUT columns (`out_user_id`, `out_is_member`) and
qualifying every `trials` reference. Verified against real Stripe: cancel now
sets `is_member = false`.

## Notes

**Trial vs billing period** — these are separate and both are correct:
- *Billing period (Monthly)* lives on the Stripe price: how often you charge
- *Trial (7 days)* lives in `create-checkout`: how long before the first charge

Stripe greys out the billing period on an existing price because changing it
would alter the schedule for anyone already subscribed. A different period
needs a new price.

**Timezone** — `subscribed_until` is stored in UTC (`+00`). In PH time (UTC+8)
a trial ending `Oct 14 18:56 UTC` is `Oct 15, 2:56 AM`.
